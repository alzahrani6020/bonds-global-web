# BONDS Architecture Conflicts — تعارضات المعمارية

> **الإصدار:** 1.0-draft  
> **المرجع الأعلى:** `docs/BONDS_CONSTITUTION.md`  
> **النوع:** وثيقة هندسية — لا يحتوي على كود

---

## 1. الهدف

توثيق أي تعارض بين الدستور/المعايير والتنفيذ الحالي، مع اقتراح حلول. لا يتم تجاوز الدستور؛ يتم توثيق المشكلة والحل المقترح.

---

## 2. قائمة التعارضات

### C1 — وجود 226 صفحة حاسبة منفصلة

| البند | التفاصيل |
|---|---|
| **التعارض** | `BONDS_CONSTITUTION.md` ينص على إلغاء مفهوم الحاسبات المنفصلة وتحويلها إلى Expert Engines. |
| **الواقع** | المشروع يحتوي على 226 صفحة HTML في `calculators/` و `en/calculators/`. |
| **الأسباب التاريخية** | BONDS بدأت كمجموعة حاسبات مستقلة قبل تحولها إلى منصة. |
| **الحل المقترح** | تدريجياً تحويل كل حاسبة إلى Expert Engine يُستدعى داخل رحلة موحدة، وإعادة توجيه الصفحات القديمة إلى الرحلة الجديدة. |
| **الأولوية** | Critical |

---

### C2 — ترحيلات V3 خارج `supabase/migrations/`

| البند | التفاصيل |
|---|---|
| **التعارض** | `09_DATABASE_STANDARD.md` M1 ينص على أن جميع التغييرات تكون عبر migrations في `supabase/migrations/`. |
| **الواقع** | `v3/supabase/migrations/` تحتوي على 22 migration منفصلة. |
| **الأسباب التاريخية** | V3 بدأ كمشروع فرعي مستقل. |
| **الحل المقترح** | دمج/نقل كل ترحيلات V3 إلى `supabase/migrations/` مع ترقيم زمني موحد. |
| **الأولوية** | High |

---

### C3 — بيانات جغرافية/قطاعية ثابتة في JS

| البند | التفاصيل |
|---|---|
| **التعارض** | `04_DATA_STANDARD.md` M4 ينص على عدم وضع بيانات ثابتة في الكود. |
| **الواقع** | `calculators/country-platforms-data.js`، `calculators/shared-platforms.js`، `v3/master-data/countries-governorates-cities.js` تحتوي على آلاف الأسطر. |
| **الأسباب التاريخية** | الحاجة إلى سرعة تحميل البيانات بدون API. |
| **الحل المقترح** | نقل البيانات إلى جداول Supabase وتحميلها ديناميكياً مع caching. |
| **الأولوية** | High |

---

### C4 — تكرار بيانات المستخدم بين `auth.users` و `profiles`

| البند | التفاصيل |
|---|---|
| **التعارض** | `04_DATA_STANDARD.md` M1 — Single Source of Truth. |
| **الواقع** | `profiles` يخزن email, phone, country, city, branch_count, ... وهي موجودة في `auth.users` أو metadata. |
| **الأسباب التاريخية** | رغبة في الوصول السريع إلى بيانات المستخدم. |
| **الحل المقترح** | استخدام view أو قراءة من `auth.users` و `user_metadata`، والاحتفاظ بـ `profiles` للبيانات الإضافية فقط. |
| **الأولوية** | High |

---

### C5 — V3 router مغلّف في `api/v3/index.js`

| البند | التفاصيل |
|---|---|
| **التعارض** | `01_ARCHITECTURE_STANDARD.md` M5 + `08_API_STANDARD.md` M5 ينصان على توجيه V3 عبر `v3/api/index.js`. |
| **الواقع** | `vercel.json` يوجه `/api/v3/*` إلى `/api/v3/index` ثم إلى `v3/api/index.js`. |
| **الأسباب التاريخية** | إعدادات Vercel القديمة. |
| **الحل المقترح** | توجيه `/api/v3/*` مباشرة إلى `v3/api/index.js` وإزالة `api/v3/index.js`. |
| **الأولوية** | High |

---

### C6 — CORS wildcard على APIs المصادقة

| البند | التفاصيل |
|---|---|
| **التعارض** | `07_SECURITY_STANDARD.md` M4 — CORS headers. |
| **الواقع** | `vercel.json` يضع `Access-Control-Allow-Origin: *` على `/api/*` و `/api/v3/*`. |
| **الأسباب التاريخية** | تسهيل التطوير والاختبار. |
| **الحل المقترح** | تقييد CORS على النطاقات المعروفة للـ endpoints المصادقة، والاحتفاظ بـ wildcard للقراءة العامة فقط. |
| **الأولوية** | High |

---

### C7 — اللغة العربية فقط في قوالب AI

| البند | التفاصيل |
|---|---|
| **التعارض** | `02_UI_UX_STANDARD.md` M4 — دعم اللغتين. |
| **الواقع** | `lib/ai/prompts.js` يستخدم النص العربي فقط؛ الواجهة الإنجليزية تنتج تقارير عربية. |
| **الأسباب التاريخية** | BONDS بدأت عربية ثم أُضيفت النسخة الإنجليزية. |
| **الحل المقترح** | بناء قوالب AI ثنائية اللغة يتم اختيارها حسب `lang`. |
| **الأولوية** | Medium |

## 3. كيفية التعامل مع التعارضات

1. توثيق التعارض هنا.
2. عدم تجاوز الدستور أو المعايير.
3. اقتراح الحل الأقل تكلفة وأعلى أثر.
4. إدراج الحل في خارطة الطريق.
5. تنفيذ الحل بعد موافقة المهندس المعماري.

---

## 4. الملاحظات

- التعارضات الحالية ناتجة بشكل أساسي عن تحول المنصة من موقع حاسبات إلى منصة قرار.
- يجب معالجة التعارضات Critical أولاً قبل إضافة أي ميزة جديدة.
