## 4. المكونات

| المكون | الوظيفة |
|---|---|
| **Scheduler** | جدولة التحليلات الدورية والفورية. |
| **Orchestrator** | تنسيق تنفيذ المحركات حسب workflow. |
| **Priority Queue** | ترتيب المهام حسب الأهمية والاستعجال. |
| **Event Bus** | استقبال وتوزيع الأحداث. |
| **Engine Manager** | إدارة حالة وصحة المحركات. |
| **Data Coordinator** | ضمان توفر البيانات الصحيحة قبل التحليل. |
| **Performance Monitor** | مراقبة أداء كل مكون. |

---

## 5. سير مهمة قرار

```text
User Intent → Parse → Fetch Data → Queue → Run Engines
    → Score Confidence → Generate Report → Review → Certify → Deliver
```

---

## 6. أولويات التنفيذ

| الأولوية | الحالة |
|---|---|
| Critical | تنفيذ فوري: أخطاء، مخالفات، تنبيهات Critical. |
| High | تنفيذ سريع: طلبات مستخدم، توصيات High. |
| Medium | تنفيذ ضمن الثواني/الدقائق: تحليلات دورية. |
| Low | تنفيذ في الخلفية: تحديثات كتالوج، تعلم ذاتي. |

---

## 7. إدارة الأحداث

| نوع الحدث | المصدر | الاستجابة |
|---|---|---|
| Data Updated | Live Intelligence | إعادة حساب المشاريع المتأثرة. |
| User Action | UI | تشغيل workflow مناسب. |
| Threshold Crossed | Autonomous Intelligence | إنشاء تنبيه. |
| Plugin Event | Plugin Runtime | توجيه للـ Plugin المعني. |
| System Alert | Monitoring | إشعار فريق التشغيل. |

---

## 8. الحوكمة

- كل مهمة لها هوية وAudit Trail.
- لا يُسمح بتشغيل محرك دون التحقق من صلاحية البيانات.
- يجب أن يكون النظام قادراً على Pause/Resume/Cancel لأي مهمة.
