## 4. الطبقات والوظائف

| الطبقة | الوظيفة |
|---|---|
| **Sources Layer** | جمع البيانات من APIs، DBs، files، user inputs. |
| **Ingestion Layer** | توحيد الصيغ، الجداولة، معالجة الأخطاء. |
| **Catalog Layer** | فهرسة جميع الأصول الرقمية و Metadata. |
| **Quality Layer** | فحص القواعد، كشف التكرار، التحقق من الصلاحية. |
| **Master Data Layer** | إنشاء Golden Records للكيانات الرئيسية. |
| **Lineage Layer** | تتبع أصل وتحول كل بيانة. |
| **Access Layer** | توفير واجهة موحدة للمحركات والتطبيقات. |

## 6. إدارة جودة البيانات

| القاعدة | الوصف |
|---|---|
| **Completeness** | نسبة الحقول المكتملة. |
| **Accuracy** | مطابقة المصدر الموثوق. |
| **Consistency** | عدم التضارب بين مصادر مختلفة. |
| **Timeliness** | حداثة البيانات. |
| **Validity** | مطابقة الأنواع والنطاقات. |
| **Uniqueness** | عدم وجود تكرار. |

---

## 7. إزالة التكرار وكشف التضارب

- **Deduplication key**: مجموعة حقول تُميز الكيان (مثال: country + city + project_type + date).
- **Conflict rule**: عند تضارب قيمتين، تُرفع إلى Data Steward للمراجعة.
- **Auto-merge**: إذا كان الفرق ضمن نسبة مقبولة، يُستخدم المتوسط.
- **Golden Record**: النسخة النهائية المعتمدة بعد المراجعة.

---

## 8. Data Lineage

كل بيانة تحتفظ بسلسلة:

```text
Source → Ingestion → Transformation → Validation → Storage → Consumption
```

يجب أن تكون كل خطوة قابلة للعرض والتدقيق.

---

## 9. النسخ والمزامنة

- **Versioning**: كل تغيير في البيانات يُنشئ نسخة جديدة.
- **Sync**: المزامنة بين المصادر والمنصة وفق الجداول الزمنية.
- **Conflict resolution**: عند تعارض النسخ، يُستخدم Last-Writer-Wins أو Manual Review حسب الحساسية.

---

## 10. صلاحية البيانات

- كل بيانة تحمل `valid_from` و `valid_until`.
- البيانات المنتهية لا تُستخدم في حسابات جديدة.
- يُسمح بالاحتفاظ بالتاريخية للتحليل والتدقيق.
