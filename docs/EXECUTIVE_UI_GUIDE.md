# دليل واجهة المستخدم التنفيذية — BONDS Executive UI Guide

> **البرنامج:** BONDS Product Transformation Program (PTP) — Wave 3  
> **التاريخ:** 2026-07-02

---

## 1. الهدف

تصميم واجهات تشعر المستخدم بأنه يستخدم منصة مؤسسية عالمية لاتخاذ القرار، وليس مجموعة صفحات.

---

## 2. المبادئ

### 2.1 تدرج المعلومات

- **الرقم الرئيسي أولاً:** في كل بطاقة أو قسم، اعرض أهم رقم/قرار في الأعلى.
- **التفاصيل لاحقاً:** ضع التفاصيل في تبويبات أو أقسام قابلة للطي.
- **لا تكدس:** لا تعرض أكثر من 5–7 عناصر بارزة في الشاشة الواحدة.

### 2.2 التبويبات

استخدم التبويبات لتنظيم المحتوى الكثيف:

- نظرة عامة
- خط الزمن
- الموافقات
- الإنذارات
- المستندات

### 2.3 البطاقات الموحدة

كل بطاقة تحتوي على:

- عنوان واضح.
- قيمة رئيسية (رقم أو حالة).
- وصف قصير.
- إجراء اختياري.

### 2.4 Empty States

عند عدم وجود بيانات:

- اعرض أيقونة واضحة.
- اشرح الخطوة التالية.
- قدّم CTA واضح.

### 2.5 التحديث الحي

- اعرض وقت آخر تحديث.
- استخدم spinner صغير أثناء التحميل.
- تجنب `alert()`؛ استخدم إشعارات داخلية.

### 2.6 الأيقونات

- استخدم SVG موحد.
- لا تستخدم إيموجي في dashboards.
- كل حالة لها أيقونة ثابتة.

### 2.7 الوصول

- جميع العناصر التفاعلية هي `<button>` أو `<a>`.
- استخدم `aria-expanded` للقوائم.
- استخدم `aria-live` للتحديثات.
- تأكد من تباين الألوان.

## 4. أمثلة

### بطاقة مقياس

```html
<div class="ecc-metric">
  <div class="ecc-metric__value">87</div>
  <div class="ecc-metric__label">جاهزية الاستثمار</div>
  <div class="ecc-metric__status status--healthy">ممتازة</div>
</div>
```

### تنبيه

```html
<div class="ecc-alert ecc-alert--warning">
  <svg class="ecc-icon">...</svg>
  <div>
    <div class="ecc-alert__title">جاهزية منخفضة</div>
    <div class="ecc-alert__msg">درجة الجاهزية أقل من الحد الأدنى.</div>
  </div>
</div>
```
