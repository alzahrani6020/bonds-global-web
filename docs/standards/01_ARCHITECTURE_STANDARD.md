# 01 — Architecture Standard (معيار المعمارية)

## الهدف
تحويل BONDS إلى منصة ذكاء اقتصادي متكاملة، بحيث لا يوجد أي جزء معزول، وكل مكون يخدم قراراً استثمارياً واحداً ضمن رحلة موحدة.

## النطاق
- جميع مجلدات المشروع (`calculators/`, `en/`, `admin/`, `api/`, `v3/`, `valuation/`, `lib/`, `components/`).
- جميع الملفات الجديدة والمعدّلة.
- جميع نقاط النهاية (API endpoints).

---

## القواعد الإلزامية (Mandatory)

### M1 — لا يوجد "حاسبات" منفصلة
- يُمنع إنشاء صفحات أو مسارات أو مكونات تحمل اسم `calculator` أو `حاسبة`.
- كل أداة حسابية سابقة يجب أن تُحوّل إلى **محرك خبرة (Expert Engine)**.

### M2 — كل محرك Expert Engine
- يملك مسؤولية واضحة.
- يستقبل بيانات مدخلة موحدة.
- يُنتج نتيجة بـ **هيكل JSON موحد** يحتوي على:
  - `result`
  - `confidenceScore`
  - `dataQualityScore`
  - `methodology`
  - `warnings`
  - `metadata`

### M3 — BONDS Intelligence Core
- لا يُسمح بمحرك يقرأ أو يكتب بيانات مباشرة إلى/من محرك آخر.
- كل التواصل بين المحركات يمر عبر **النواة المركزية** أو آلية event موحدة.

### M4 — طبقة بيانات موحدة
- كل بيانات المستخدم تُخزن مرة واحدة فقط.
- يُمنع تكرار جداول أو حقول تحمل نفس المعنى.
- المحركات تقرأ من نفس المصدر وتكتب إلى نفس المصدر.

### M5 — عدم تجاوز حد Vercel
- جميع نقاط نهاية V3 يجب أن تمر عبر `v3/api/index.js`.
- لا يُنشأ ملف جديد في `api/` إذا كان سيُضاف كدالة مستقلة.

### M6 — لا صفحات أو مسارات مستقلة خارج الرحلة
- لا يُنشأ مسار عام (`/some-tool`) لا يرتبط برحلة مستخدم محددة.
- كل شاشة يجب أن تكون خطوة ضمن رحلة intent-based.

---

## القواعد الموصى بها (Recommended)

### R1 — إعادة استخدام المحركات
- كل محرك يجب أن يكون قابلاً للاستدعاء من عدة رحلات.

### R2 — الوثائق
- كل محرك يملك تعليق توضيحي في رأس الملف يوضح:
  - المسؤولية.
  - المدخلات.
  - المخرجات.
  - المحركات التي تعتمد عليه.

---

## أمثلة

### ✅ صحيح
```
valuation/valuation-engine.js   → Expert Engine
lib/ai/valuation-analyze-handler.js → يستدعي Orchestrator
```

### ❌ خاطئ
```
calculators/new-tool.html        → صفحة حاسبة منفصلة
api/new-feature.js               → دالة Vercel جديدة
```

---

## كيفية القياس
1. `grep -R "calculator\|حاسبة" --include="*.html" --include="*.js" --include="*.md" .`
2. فحص `vercel.json` و `v3/api/index.js` لكل مسار جديد.
3. مراجعة `package.json` dependencies بحثاً عن مكتبات معزولة.

## Severity عند المخالفة
- **Critical:** صفحة أو API حاسبة جديدة.
- **High:** محرك لا يستخدم النواة المركزية.
- **Medium:** بيانات مكررة أو جداول متداخلة.
- **Low:** نقص الوثائق.

## طريقة الإصلاح
- تحويل الحاسبة إلى محرك Expert Engine.
- توجيه API عبر `v3/api/index.js`.
- دمج البيانات المكررة في جدول مركزي.
- توثيق المحرك في `docs/engines/`.
