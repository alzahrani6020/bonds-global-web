# 07 — Security Standard (معيار الأمن)

## الهدف
حماية بيانات المستخدمين والأسرار والبنية التحتية، وضمان امتثال المنصة لأفضل ممارسات الأمن.

## النطاق
- جميع نقاط النهاية (APIs).
- جميع ملفات الواجهة الأمامية (HTML/JS/CSS).
- جميع جداول قاعدة البيانات.
- جميع متغيرات البيئة (env vars).

---

## القواعد الإلزامية (Mandatory)

### M1 — لا أسرار في الواجهة الأمامية
- لا يُعرض `STRIPE_SECRET_KEY`، `OPENAI_API_KEY`، `SUPABASE_SERVICE_ROLE_KEY`، أو أي سر في HTML/JS.
- الأسرار تبقى في الخادم فقط.

### M2 — المصادقة والتفويض
- جميع نقاط النهاية الحساسة تتطلب مصادقة صالحة.
- يجب التحقق من ملكية المورد (ownership) قبل القراءة/الكتابة.
- يجب استخدام RLS على جميع الجداول.

### M3 — التحقق من المدخلات
- جميع المدخلات من المستخدم يجب التحقق منها.
- يُمنع تمرير قيم مباشرة إلى استعلامات قاعدة البيانات.

### M4 — CORS Headers
- جميع نقاط النهاية يجب أن تُعيد رؤوس CORS صحيحة.
- `Content-Type` و `Authorization` مسموح بهما.

### M5 — HTTPS
- جميع الموارد يجب أن تُحمّل عبر HTTPS في الإنتاج.

### M6 — RLS Policies
- كل جدول جديد يجب أن يفعّل RLS.
- يجب أن تحتوي على سياسات SELECT و ALL مناسبة.
- يجب أن تحتوي على سياسة `service_role` للعمليات الإدارية.

---

## القواعد الموصى بها (Recommended)

### R1 — Rate Limiting
- تطبيق حدود معدل الطلبات على APIs الحساسة.

### R2 — Audit Logging
- تسجيل العمليات الحساسة (إصدار شهادة، حذف بيانات، تعديل أدوار).

---

## أمثلة

### ✅ صحيح
```js
const stripeSecret = process.env.STRIPE_SECRET_KEY;
// تُستخدم فقط في الخادم
```

### ❌ خاطئ
```html
<script>
  const API_KEY = 'sk_live_...';
</script>
```

---

## كيفية القياس
1. `npm run audit` — يفحص الأسرار.
2. `grep -R "STRIPE\|OPENAI\|SUPABASE_SERVICE" --include="*.html" --include="*.js" .`
3. مراجعة RLS policies في `supabase/migrations/`.
4. فحص كل API endpoint للتحقق من `getUserFromToken` أو ما يعادله.

## Severity عند المخالفة
- **Critical:** سر مكشوف في الواجهة الأمامية.
- **Critical:** API حساس بدون مصادقة.
- **High:** جدول بدون RLS.
- **Medium:** عدم التحقق من المدخلات.
- **Low:** نقص audit logging.

## طريقة الإصلاح
- إزالة الأسرار من الواجهة.
- إضافة مصادقة لكل API حساس.
- إضافة RLS policies.
- استخدام prepared statements أو ORM.
