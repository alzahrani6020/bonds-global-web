# 06 — Calculation Standard (معيار الحسابات)

## الهدف
جعل جميع الحسابات شفافة، قابلة للمراجعة، مختبرة، ومبنية على معايير واضحة.

## النطاق
- جميع محركات الحساب (`valuation-engine.js`, `depreciation-engine.js`, `risk-intelligence-engine.js`, ...).
- جميع الدوال الحسابية في `calculators/`.
- جميع الاختبارات الحسابية.

---

## القواعد الإلزامية (Mandatory)

### M1 — عزل منطق الحساب
- كل حساب يجب أن يكون في دالة مستقلة مع اسم واضح.
- لا يُسمح بوضع منطق حسابي معقد مباشرة في ملف HTML.

### M2 — لا أرقام سحرية
- كل ثابت يجب أن يُعرّف في أعلى الملف أو في ملف `standards`.
- يُمنع استخدام `0.15` أو `12` دون تسمية.

### M3 — الوحدة والدقة
- يجب توثيق وحدة كل قيمة (مثلاً ريال سعودي، سنة، نسبة مئوية).
- يجب استخدام `toFixed` أو `Math.round` بشكل متناسق.

### M4 — الاختبارات
- كل دالة حسابية غير تافهة يجب أن يكون لها unit test.
- الحد الأدنى: تغطية الحالات الطبيعية والحدودية.

### M5 — Standards-Driven
- كل حساب يجب أن يشير إلى المعيار أو المصدر الذي يعتمد عليه.
- مثال: `BONDS Valuation Standards (BVS)`، `IFRS`، `SAMA`.

### M6 — النتائج الموحدة
- كل محرك يُنتج نتيجة بـ schema موحد يحتوي على القيمة، الثقة، المنهجية، والتحذيرات.

---

## القواعد الموصى بها (Recommended)

### R1 — Sensitivity Analysis
- كل محرك يقدم تحليل حساسية للمتغيرات الرئيسية.

### R2 — Audit Trail
- يمكن تتبع كيف وصلت كل نتيجة إلى قيمتها.

---

## أمثلة

### ✅ صحيح
```js
const VAT_RATE = 0.15;

function calculateTotalWithVat(amount) {
  if (amount < 0) throw new Error('Amount must be non-negative');
  return amount * (1 + VAT_RATE);
}
```

### ❌ خاطئ
```js
let total = price * 1.15;
```

---

## كيفية القياس
1. `grep -R "function" --include="*.js" valuation/ calculators/ | grep -i "calc\|compute"`.
2. مراجعة كل ملف بحثاً عن أرقام سحرية.
3. تشغيل `npm test`.
4. مراجعة تغطية الاختبارات.

## Severity عند المخالفة
- **Critical:** حسابات بدون اختبارات في مسارات مالية رئيسية.
- **High:** أرقام سحرية في منطق مالي.
- **Medium:** عدم توثيق الوحدة.
- **Low:** عدم وجود sensitivity analysis.

## طريقة الإصلاح
- استخراج الأرقام السحرية إلى ثوابت.
- نقل الحسابات إلى دوال منفصلة.
- إضافة unit tests.
- توثيق المصدر/المعيار.
