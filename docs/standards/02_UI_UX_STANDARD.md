# 02 — UI/UX Standard (معيار تجربة وواجهة المستخدم)

## الهدف
جعل المستخدم يركز على **اتخاذ القرار** لا على تشغيل الأدوات. كل رحلة تبدأ بالنية وتنتهي بتوصية واضحة.

## النطاق
- جميع صفحات HTML (`*.html`).
- جميع وحدات التحكم في الواجهة (`*-ui.js`).
- جميع مكونات الواجهة (`components/`).

---

## القواعد الإلزامية (Mandatory)

### M1 — Intent-First
- أول سؤال يظهر للمستخدم دائماً: **"ما الذي تريد تحقيقه؟"**
- لا يبدأ المستخدم باختيار حاسبة أو أداة.

### M2 — لا صفحات حاسبات مستقلة
- لا يُسمح بصفحات تحمل في عنوانها أو مسارها `calculator` أو `calc` أو `حاسبة`.
- يُعرض كل محرك ضمن رحلة مركبة (wizard أو dashboard).

### M3 — رحلة ديناميكية
- النظام يحدد تلقائياً:
  - نوع المشروع.
  - نوع الأصل.
  - نوع الدراسة/التقييم/التمويل.
  - نوع التقرير.

### M4 — دعم اللغتين والاتجاهين
- العربية: `lang="ar" dir="rtl"`.
- الإنجليزية: `lang="en" dir="ltr"`.
- كل صفحة عربية يجب أن يكون لها نظير إنجليزي (إذا كانت عامة).

### M5 — Responsive & Accessible
- جميع الشاشات يجب أن تعمل على الشاشات الصغيرة.
- جميع العناصر التفاعلية قابلة للوصول من لوحة المفاتيح.
- يجب أن تمر على `axe-core` دون أخطاء critical.

### M6 — المكونات الموحدة
- يجب استخدام مكونات `components/` المشتركة (مثل `universal-dropdown`).
- لا يُنشأ select منسدل مخصص جديد إذا كان المكون الموحد يفي بالغرض.

---

## القواعد الموصى بها (Recommended)

### R1 — Personalization
- حفظ مسودة المستخدم تلقائياً.
- تذكر الإعدادات والتفضيلات.

### R2 — Progressive Disclosure
- إظهار المعلومات المعقدة تدريجياً حسب تقدم المستخدم.

---

## أمثلة

### ✅ صحيح
```html
<section id="intentSelector">
  <h1>ما الذي تريد تحقيقه؟</h1>
  <button>أريد تقييم أصل</button>
  <button>أريد دراسة جدوى</button>
</section>
```

### ❌ خاطئ
```html
<h1>حاسبة نقطة التعادل</h1>
<input type="number" ...>
```

## كيفية القياس
1. `grep -R "calculator\|حاسبة\|Calc" --include="*.html" .`
2. تشغيل `npm run test:a11y`.
3. تشغيل `npm run test:mobile`.
4. مراجعة كل مسار HTML لوجود رحلة واضحة.

## Severity عند المخالفة
- **Critical:** صفحة حاسبة مستقلة جديدة.
- **High:** رحلة لا تبدأ بالنية.
- **Medium:** مشكلة responsive أو accessibility.
- **Low:** عدم استخدام مكون مشترك.

## طريقة الإصلاح
- تحويل الصفحة إلى خطوة داخل رحلة wizard.
- إضافة intent selector في بداية الرحلة.
- إصلاح أخطاء accessibility.
- استبدال العناصر المكررة بالمكونات المشتركة.
