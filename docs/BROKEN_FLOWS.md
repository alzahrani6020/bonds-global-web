# الرحلات المكسورة — Broken Flows

> **البرنامج:** BONDS Product Transformation Program (PTP) — Wave 1  
> **الهدف:** توثيق الرحلات التي لا تعمل أو تنتهي بشكل غير متوقع أو تفقد السياق.

---

## 1. ملخص

يوجد عدة رحلات رئيسية في المنصة تعاني من انقطاعات. هذه الرحلات لا تُظهر أخطاء تقنية (الاختبارات تمر)، لكنها تفشل في تحقيق هدف المستخدم أو تسبب ارتباكاً.

---

## 2. الرحلات المكسورة

### 2.1 الرحلة من الصفحة الرئيسية إلى المشروع

| الخطوة | المشكلة | التأثير |
|---|---|---|
| Homepage CTA | يطلب تسجيل الدخول فوراً بدون عرض قيمة | خسارة زوار |
| بعد التسجيل | لا يوجد onboarding يوجه المستخدم | تشتت |
| إنشاء مشروع | لا يوجد ربط تلقائي بدراسة الجدوى/التقييم | المستخدم عالق |

**الحالة:** مكسورة من حيث التحويل، ليست تقنياً.

### 2.2 الرحلة من الحاسبة إلى التقرير

| الخطوة | المشكلة | التأثير |
|---|---|---|
| فتح حاسبة | المستخدم يدخل بيانات كثيرة | جهد مكرر |
| النتيجة | زر "تحليل AI" أو "تقرير" يطلب تسجيل الدخول | انقطاع |
| بعد الدخول | البيانات قد لا تُحمل تلقائياً إلى المشروع | إعادة إدخال |
| التقرير | لا يوجد PDF حقيقي، فقط طباعة المتصفح | جودة منخفضة |

**الحالة:** مكسورة؛ لا توجد رحلة موحدة.

### 2.3 رحلة الشراء والاشتراك

| الخطوة | المشكلة | التأثير |
|---|---|---|
| التسعير | الصفحة تخلط SaaS وخدمات استشارية | ارتباك |
| الترقية | في البوابة تظهر كـ `alert` | تجربة سيئة |
| Checkout | لا يتطلب auth دائماً؛ بعض endpoints عامة | مخاطر |
| نجاح الدفع | يحول إلى `calculators/restaurant.html?subscribed=1` بغض النظر عن مصدر الدخول | فقدان السياق |
| الفاتورة | لا يوجد سجل فواتير | دعم ضعيف |

**الحالة:** مكسورة من حيث تجربة المستخدم والأمان.

### 2.4 رحلة طلب مراجعة خبير

| الخطوة | المشكلة | التأثير |
|---|---|---|
| طلب المراجعة | لا يوجد حقل لإضافة ملاحظات أو مرفقات | نقص بيانات |
| الدفع | لا يوجد بوابة دفع أو تسعير واضح | لا يمكن إتمامها |
| التتبع | لا يوجد حالة أو ETA | قلق المستخدم |
| الإشعار | لا يوجد بريد إلكتروني | تجربة صامتة |

**الحالة:** مكسورة بالكامل تقريباً.

### 2.5 رحلة المشروع في V3 (الجديدة)

| الخطوة | المشكلة | التأثير |
|---|---|---|
| إنشاء مشروع | قد يظهر خطأ "لا يوجد سجل عميل" | يمنع المستخدم |
| التقييم | النتائج لا تتدفق تلقائياً إلى التمويل | إعادة إدخال |
| التمويل | DSCR يُعرض لكن لا يرتبط بالتقرير | انقطاع |
| النشرة | يمكن تحميلها قبل مراجعة AI | فقدان الثقة |
| غرفة البيانات | غير موجودة بعد | الرحلة غير مكتملة |

**الحالة:** مكسورة جزئياً؛ بعض المراحل موجودة لكنها غير مترابطة.

### 2.6 رحلة المستثمر/الشريك

| الخطوة | المشكلة | التأثير |
|---|---|---|
| الوصول | لا يوجد مسار واضح للمستثمرين | فقدان فرص |
| عرض الفرص | لا توجد قائمة مشاريع عامة | عزل |
| غرفة البيانات | غير موجودة | لا يمكن إجراء due diligence |

**الحالة:** غير موجودة تقريباً.

### 2.7 رحلة المصادقة

| الخطوة | المشكلة | التأثير |
|---|---|---|
| صفحات متعددة | `/auth.html`, `/auth-v2.html`, `/calculators/auth/`, V3 auth | ارتباك |
| مشاريع مختلفة | المستخدم قد يسجل في أحدهما ولا يرى مشاريعه في الآخر | فقدان بيانات |
| تسجيل خروج | قد لا يمسح كل الجلسات | مشاكل أمنية/تجربة |

**الحالة:** مكسورة.

---

## 4. التوصيات

1. **رسم خريطة رحلة موحدة** تبدأ بالنية وتنتهي بالتقرير/الشهادة.
2. **إزالة جدار تسجيل الدخول** من الصفحة الرئيسية والحاسبات؛ استخدام نموذج lead أو trial.
3. **توحيد المصادقة** تحت V3/Supabase مع redirect واضح.
4. **ربط المحركات** بحيث تتدفق البيانات: مشروع → تقييم → تمويل → جدوى → نشرة → مراجعة → شهادة.
5. **إنشاء صفحة نجاح دفع** واحدة تخدم السياق (SaaS vs خدمة).
6. **إضافة غرفة بيانات افتراضية (VDR)** للمستثمرين.
7. **إضافة تتبع لطلبات المراجعة** مع حالات وETA وإشعارات.
